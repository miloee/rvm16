Preface

This manual specifies RVM16, a strict 16-bit RISC-V instruction set for embedded systems. It is a proposal and a research prototype, not a ratified RISC-V International specification.

RVM16 keeps the standard RVC encodings in quadrants 00, 01, and 10 unchanged, and reuses quadrant 11, which the standard ISA reserves for 32-bit instructions, as a new 16-bit extension space called Q3. Every instruction is 16 bits wide. There are no 32-bit instruction encodings.

The manual follows the structure and conventions of the RISC-V Instruction Set Manual: a normative programming model, extension chapters, instruction descriptions with encoding tables, and an opcode map.

Intended audience

This document is for architects, compiler and simulator developers, and embedded system designers who need to evaluate or implement RVM16.

Sources

The RVC encodings are inherited from the RISC-V C extension. The Q3 formats were designed for this proposal. The F32 subset follows the RISC-V F extension semantics where applicable, with two-address forms.

Document Conventions

Bit notation

Instruction fields are written as instruction[hi:lo], with bit 15 the most significant bit of the 16-bit instruction word. The prefix 0b denotes a binary literal. The two least-significant bits of every Q3 instruction are 0b11.

Register notation

Integer registers are x0-x31; the ABI names zero, ra, sp, gp, tp, t0-t6, s0-s11, and a0-a7 are used in examples. Floating-point registers are f0-f15 in Q3; f16-f31 are outside the Q3 encoding. x31 is reserved as an expansion scratch register and shall not be allocated by compilers.

Normative language

The key words shall, shall not, should, should not, and may are to be interpreted as described in RFC 2119.

1. Introduction

1.1 Motivation

Code size is a first-order constraint in embedded systems. RVC compresses common instructions to 16 bits, but a program that contains any uncompressible 32-bit instruction still fetches four bytes for that instruction. RVM16 removes the 32-bit encoding entirely: the instruction stream is a sequence of 16-bit parcels, and a 32-bit operation is assembled from one or two parcels.

1.2 Scope

RVM16 is a 32-bit data-path ISA with 32 general-purpose registers, a mandatory F32 floating-point unit, and a 16-bit instruction encoding. This volume specifies the base integer instructions, the M extension, the F extension, CSRs, and machine-mode system instructions. The A extension is reserved for a future revision.

1.3 Compatibility

RVM16 is encoding-compatible with RVC: every RVC instruction in quadrants 00, 01, and 10 keeps its standard encoding. It is not binary-compatible with RV32IMAF_C programs that contain 32-bit instructions; such programs must be recompiled. The ABI is ILP32F.

1.4 Naming

RVM16 is a working name. Alternative names considered were RVM32E16, RV16E, and RVA-E16. The name does not imply an existing RISC-V profile family.

The ABI uses ILP32F: 32-bit pointers, F32 arguments and returns in f0-f7, f8-f15 callee-saved, and a 16-byte aligned stack.

2.2 Memory

Memory is little-endian. Loads and stores support byte, halfword, and word accesses. Word accesses shall be naturally aligned. Misaligned accesses may raise a load or store address-misaligned exception.

2.3 Instruction alignment

Every instruction is 2 bytes. Branch and jump targets shall be 2-byte aligned. A target with bit 0 set raises an instruction-address-misaligned exception.

2.4 Privilege

RVM16 supports machine mode (M), and may support user mode (U). Supervisor mode and virtual memory are outside the scope of this volume.

3. Encoding Framework

3.1 Instruction length

Every instruction is 16 bits. The two least-significant bits select the quadrant. Quadrants 00, 01, and 10 are RVC. Quadrant 11 is Q3. The name Q3 means quadrant 3 of the 2-bit quadrant field; standard RISC-V uses this quadrant as the 32-bit instruction escape, while RVM16 redefines it as a 16-bit space.

3.3 Field notation

A Q3 encoding is written as (f4 << 12) OR payload OR 0b11, where payload occupies bits 11:2. The payload layout depends on the block. Registers in 3-bit fields are x8-x15; 4-bit fields are x0-x15; 5-bit fields are x0-x31.

4. Base Integer Instructions

4.1 RVC inheritance

The RVC instructions in quadrants 00, 01, and 10 are unchanged. Compilers may use c.li, c.lui, c.addi, c.andi, c.slli, c.srli, c.srai, c.add, c.sub, c.and, c.or, c.xor, c.mv, c.lw, c.sw, c.lwsp, c.swsp, c.beqz, c.bnez, c.j, c.jal, c.jr, c.jalr, c.nop, and c.ebreak with their standard encodings.

4.2 Two-address execution model

Q3 integer ALU instructions are two-address: the destination is also the first source. A three-address operation rd = rs1 op rs2 is assembled as a copy rd = rs1 followed by the Q3 operation on rd and rs2, or by a sequence of RVC instructions when the registers fit the RVC x8-x15 fields. The compiler is responsible for this expansion.

5.4 Load and store format

Loads and stores use f4 = 7 or 8, a 2-bit funct2 in bits 11:10, a 4-bit register field in bits 9:6 (encoding x0-x15), a 2-bit base selector in bits 5:4, a 2-bit offset field in bits 3:2, and 0b11. The base selector encodes 0 = fp (x8), 1 = dp (x9), 2 = sp (x2), 3 = gp (x3). The offset is scaled by the access size, giving a 4-byte window for word accesses. The 4-bit register field includes ra (x1), so a non-leaf function can spill and reload its return address.

6. M Extension

The M extension is implemented by the CA3 block (Section 5.2). C.MUL is the Zcb instruction with encoding 0x9EC9 for rd=a3, rs2=a0; it is two-address and uses x8-x15. The Q3 CA3 funct3 = 000 code point is reserved.

7. F Extension (F32)

7.1 Format

F32 Q3 instructions use f4 = 9-13, a 2-bit funct2 in bits 11:10, a 4-bit fd in bits 9:6, and a 4-bit fs2 in bits 5:2. All 16 registers f0-f15 are addressable. Arithmetic is two-address. Rounding is dynamic from frm; there is no per-instruction rounding-mode field. FMA is not implemented; a compiler expands a fused multiply-add into a multiply followed by an add.

10. Exceptions and Interrupts

An instruction-address-misaligned exception is raised when a branch or jump target has bit 0 set. A load or store address-misaligned exception is raised when a word access is not 4-byte aligned. An illegal-instruction exception is raised for an unknown encoding, for a reserved Q3 code point, or for an instruction that requires an extension that is not enabled.

The machine-mode trap CSRs are mtvec, mepc, mcause, and mtval. mcause follows the standard RISC-V cause codes.

11. ABI

RVM16 uses ILP32F with a pointer-register extension. The first two pointer arguments are passed in s0 (x8) and s1 (x9); remaining integer and pointer arguments are passed in a0-a7 (x10-x17). F32 arguments are passed in f0-f7. Integer or pointer returns are in a0; F32 returns are in f0. s0 and s1 are caller-saved argument registers in this ABI; s2-s11 and f8-f15 are callee-saved. A variadic or unprototyped call passes all integer and pointer arguments in a0-a7, so a callee without a prototype sees the standard sequence. The stack pointer is sp (x2) and shall be 16-byte aligned. x31 is reserved and shall not be used for argument passing or allocation.

The pointer-register convention is what makes the s0/s1 code-size result in Appendix C possible: a pointer argument arrives in a Q3 base register, so a load does not need a c.mv first. A standard a0-a7 ABI would require those copies at every use.

The naive expansion pays for a c.mv before each load whose base is not one of the Q3 base registers, for the two-address form of three-address ALU operations, and for compare-plus-branch sequences because Q3 has no flags. Keeping pointers in s0/s1 removes most of the load-side moves, but the conditional-branch cost remains. A fused compare-and-branch would help, but a 16-bit encoding with two 3-bit registers leaves only about four offset bits (+-16 bytes), and the FIR loop body is 18 bytes, so it needs a trampoline or a different branch design. These results are the main argument that a strict 16-bit ISA needs compiler and ISA co-design; strict width alone is not a code-size win for pointer- and branch-heavy C.
